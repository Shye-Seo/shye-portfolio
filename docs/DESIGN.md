# 디자인 노트 — shye-portfolio

이 사이트는 회사 소개형 홈페이지의 섹션 공식을 따르지 않습니다.
"작업 문서를 펼쳐 보는 색인(working index)"이라는 한 가지 생각으로 표지·케이스 파일·벤토·연락을 이었습니다.
색·타이포·레이아웃·모션의 기준을 여기에 적어 두었으니, 페이지를 고칠 때 같은 규칙 안에서 고치면 됩니다.

## 1. 방향

- **성격**: 제품을 만드는 엔지니어의 작업 문서. 장식보다 순서와 여백으로 신뢰를 만듭니다.
- **버린 공식**: 요약 지표가 붙은 히어로, 기술 마퀴, 포지션 진단 버튼 4개, 가로 단계 카드 4장,
  좌우로 번갈아 놓는 프로젝트, 6칸 지표 그리드, 화면 끝까지 채우는 다크 CTA.
- **대신 쓰는 것**: 표지 다음에 바로 펼쳐지는 **케이스 파일 워크스페이스**, 그 아래 **한 장의 벤토**,
  마지막은 큰 메일 주소 하나. 증거를 먼저 보여 주고 설명은 그 옆에 붙입니다.
- **숫자는 근거로만** 씁니다. 검증하지 못한 항목은 각 프로젝트의 ‘검증 범위’와 벤토의 ‘검증하지 못한 경계’에 남깁니다.

## 2. 읽는 순서

1. **표지** — 마스트헤드(이름·직함·지역·연도), 큰 제목 두 줄, 소개문, 프로젝트 색인 4줄.
2. **01 케이스 파일** — 프로젝트 4개가 한 줄씩 쌓인 목록. 고른 항목이 그 자리에서 펼쳐지고
   `개요 / 구조 / 문제 해결` 탭으로 내용이 바뀝니다. 오른쪽에는 실제 배포 화면 도판과 스택·테스트가 남습니다.
3. **02 벤토** — 12칸 격자 한 장. 순환하는 작업 방식(인디고 틴트 칸), 테스트 원장, 지표 3개,
   도구, 사이드 프로젝트, 검증하지 못한 경계.
4. **03 연락** — 큰 메일 주소, `주소 복사`, `메일 보내기`, GitHub·블로그 링크.

`--surface-line`(#d3defb) · `--surface-rule`(#b9caf9)로 따로 둡니다.

- 포인트는 **코발트 하나**, 스카이 틸은 상태·흐름 표시에만, 앰버는 ‘주의해서 봐야 할 것’에만 씁니다.
- **어두운 바탕 면을 쓰지 않습니다.** 선택 상태는 인디고 틴트 바탕과 왼쪽 3px 포인트 선으로,
  순환 도식은 흰 단계 카드와 틴트 바탕의 차이로 나눕니다.
- 형광 마커·그라데이션 배지·파스텔 카드처럼 눈에 띄는 장식은 쓰지 않습니다.

## 4. 타이포그래피

- 본문·제목: **Paperlogy**(400 / 500 / 700 / 800). 눈누 배포본, 상업적 사용 가능.
- 라틴 문자·숫자 라벨만 시스템 모노스페이스(`ui-monospace` 계열)로 둡니다.
  섹션 라벨, 케이스 번호, 스택·테스트 표제, 푸터에만 쓰고 **한글 문장에는 쓰지 않습니다**.
- 크기
  - 표지 제목 `clamp(2.55rem, 6vw, 5.1rem)` / line-height 1.04 / 자간 -0.052em
  - 섹션 제목 `clamp(1.9rem, 3.6vw, 2.95rem)` / line-height 1.14
  - 펼친 케이스 제목 `clamp(1.4rem, 2.4vw, 1.95rem)`
  - 벤토 숫자 `clamp(2.5rem, 4.6vw, 4rem)` / tabular-nums
  - 본문 16px / 1.72, 보조 문장 11~14px
  - 최소 글자 크기는 9px이며, 모노 대문자 라벨과 도판 캡션에만 씁니다.
- 한글은 `word-break: keep-all`로 단어 중간에서 끊기지 않게 하고, 긴 주소만 `break-all`을 씁니다.

## 5. 레이아웃

- 컨테이너 최대 1180px, 좌우 패딩 `clamp(1.25rem, 4vw, 2.75rem)`.
- 섹션 세로 여백 `clamp(4.5rem, 8vw, 7.5rem)`. 바탕은 `paper → paper → paper-2 → paper`로 한 번만 뒤집습니다.
- **표지**: 44px 왼쪽 여백 칸(세로 라벨·세로 선·십자 표시) + 큰 제목 + 356px 오른쪽 칸(소개문·색인).
  오른쪽 칸은 왼쪽 헤어라인으로 본문과 나눕니다. 900px 이하에서는 한 칸으로 쌓입니다.
- **섹션 머리(`SectionHead`)**: 위쪽 1px 검정 헤어라인, 모노 라벨과 54px 규칙, 큰 제목 + 오른쪽 설명.
  장식적인 장 번호 대신 라벨을 왼쪽에 두고 제목을 크게 씁니다.
- **케이스 파일**: 줄 하나가 `번호 · 이름 · 분류 · 테스트 · 화살표` 5칸. 열린 줄은 인디고 틴트로 바뀌고
  왼쪽에 코발트 3px 선이 섭니다. 펼친 패널은 흰 바탕, `본문 | 도판` 2칸입니다.
- **도판**: 9px 여백을 준 액자에 실제 화면을 넣고, 아래에 `도판 0N / 실제 배포 화면` 캡션을 답니다.
  브라우저 크롬을 흉내 내지 않습니다.
- **벤토**: 12칸 격자, 9px 간격, `minmax(150px, auto)` 행. 칸마다 역할이 다릅니다.
  순환 도식 5칸(2행) · 테스트 원장 4칸 · 지표 3칸 · 지표 4칸 · 지표 3칸 · 도구 7칸 · 사이드 5칸 · 경계 12칸.
- 모서리는 2~3px만 씁니다. 알약형·큰 라운드 카드는 쓰지 않습니다.
- 그림자 대신 `1px` 헤어라인과 바탕색 차이로 영역을 구분합니다.

## 6. 상호작용

- **색인 바**: 첫 화면에서는 숨고, 240px 이상 스크롤하면 위에서 내려옵니다.
  왼쪽 이름, 가운데 `01 작업 · 02 방식 · 03 연락`, 오른쪽 메일·GitHub. 맨 위 2px 선이 읽은 비율입니다.
- **케이스 아코디언**: 한 번에 하나만 열립니다. 열린 줄을 다시 누르면 닫힙니다.
  `aria-expanded`와 `aria-controls`로 상태를 알리고, 닫힌 패널은 `hidden`입니다.
- **탭**: `role="tablist"`, 선택된 탭만 `tabIndex=0`. 방향키·Home·End로 이동하고 포커스도 따라갑니다.
  패널은 `role="tabpanel"` 하나를 두고 내용만 바꿉니다.
- **주소 복사**: 클립보드 API를 쓰고, 막히면 임시 입력란과 `execCommand`로 대체합니다.
  버튼 글자가 `주소 복사 → 복사됨`으로 바뀌고, 같은 내용을 `role="status"`로 읽어 줍니다.
- **색인 링크**: 표지의 프로젝트 이름을 누르면 해당 케이스가 열린 채로 그 줄까지 스크롤합니다.

## 7. 모션

- 스크롤 리빌: `IntersectionObserver`로 `.reveal` → `.is-in`. 16px 떠오르며 0.72초(`--ease: cubic-bezier(.22,1,.36,1)`).
- 케이스 패널은 0.45초, 탭 내용은 0.32초 페이드. 열린 줄의 화살표는 180° 회전합니다.
- 숫자 카운터는 화면에 들어올 때 한 번만 0에서 목표 값까지 올라갑니다(0은 고정).
- 호버는 1~4px 이동과 색 변화까지만. `prefers-reduced-motion`에서는 리빌·카운터·전환을 모두 끕니다.

## 8. 접근성

- 모든 장식 요소는 `aria-hidden`, 의미 있는 링크·버튼은 실제 요소로 만듭니다.
- 포커스 링은 코발트 2px, `:focus-visible`에서만 보입니다.
- 본문 대비: `--muted`(#59637a)는 `--paper` 위 6.0:1, `--paper-2` 위 5.6:1, 인디고 틴트 위 5.3:1입니다.
  포인트 #2f54eb는 흰 바탕 위 5.85:1, 틴트 위 `--accent-strong`(#2141ce) 6.85:1.
  검사한 74개 텍스트 요소가 모두 4.5:1을 넘습니다.
- 케이스 표 머리는 `h3 > button`, 패널은 `role="region"`과 버튼을 `aria-labelledby`로 잇습니다.
- 색인 바는 숨은 동안 `visibility: hidden`으로 탭 순서에서 빠집니다.
- 320~1440px 사이 23개 폭에서 가로 스크롤이 없음을 확인했습니다.
